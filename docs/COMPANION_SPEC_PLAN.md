## 0. エグゼクティブサマリー

`companion-spec` は、ハードウェアに依存しない AI コンパニオンの仕様書とデプロイ機構を提供する Claude プラグインである。ユーザーは対話型の設計プロセスを通じて、人格・声・外観・記憶・感覚・ランタイムを一つのポータブルなバンドルとして記述・保存・移植できる。

現行の AI コンパニオンは例外なく**プラットフォームに囚われている**。Character.ai で育てたキャラは VRChat に持ち込めず、OpenAI のアシスタントは Meta Ray-Ban には載せられない。存在そのものを記述する**開かれた仕様**は、業界にまだ存在しない。

本プラグインは、その空白に Claude の側から楔を打つ試みである。

**位置づけの明言：** 本プラグインはポートフォリオ全体における**第四の矢**であり、`programmatic-video-gen` → `arxiv-research-toolkit` → `notion-plugin` の三本柱が公式採用されたのちに本格始動する。本文書はその着工前の設計思考を記録するための企画書である。

## 1. 背景

### 1.1 メタ社の12兆円の遺産

2026年1月、Meta 社はメタバース事業 Horizon Worlds の VR 版サービス終了（2026年6月15日）を発表した。12兆円を投じた大事業の失敗として報じられているが、**技術基盤そのものは彼らの手元で生き残り、むしろ第三者にとって使いやすい状態になった**。

- Horizon OS（旧 Quest OS）は継続開発中、Asus・Lenovo への OS ライセンス供与も始まった
- Meta Horizon Store（アプリ配布）健在
- Meta XR SDK（Unity / Unreal）アクティブ開発
- OpenXR は Khronos Group のオープン標準
- Meta Avatars SDK 継続

自社コンテンツ（Horizon Worlds）は畳んだが、**プラットフォーム層は第三者開発者に開いた**。2008年の Apple App Store 開放と構造的に酷似している。

### 1.2 AR グラスの普及期到来

2026年時点で AR グラス市場は以下の兆候を示している：

- Meta Ray-Ban（音声・カメラ搭載、数百万台販売）と次世代 Orion（ディスプレイ付き）のデモ
- Apple Vision Pro（高価だが方向性を確立）
- Xreal・Rokid 等中国勢の低価格ディスプレイ付き AR グラス
- Google + Samsung の Android XR 出荷開始（2025年末）

消費者向け AR グラスの普及期は2027年後半と予測される。12ヶ月〜18ヶ月の猶予がある。

### 1.3 AI コンパニオン市場の現状と空白

人類は既に毎日 AI と会話している。ChatGPT・Claude・Gemini・Character.ai を含む会話系 AI サービスは、合計で日次数十億回のやり取りを記録している。この習慣は**確立済み**である。

しかし、現行サービスはいずれも**自社プラットフォームに閉じたペルソナ**しか提供しない：

| サービス         | 移植性 | 器（体） | 長期記憶 |
| ---------------- | ------ | -------- | -------- |
| Character.ai     | 不可   | 2Dチャット | 限定的 |
| Replika          | 不可   | 2D/VR 独自 | 限定的 |
| OpenAI GPTs      | 不可   | テキスト | なし |
| Meta AI          | 不可   | 2D/音声 | なし |

**「あなたが育てた人格を、あなたが選ぶ任意の器に移す」ための開かれた仕様は存在しない**。これが本プラグインの対象とする空白である。

## 2. ビジョン

### 2.1 一言で

> 一つの人格、多くの表面。今日はテキスト、明日は VR、明後日は AR グラス。

### 2.2 中核思想

**存在を一次物、プラットフォームを使い捨てとみなす**。ユーザーは一度設計すれば、どのデバイスが来てもそのコンパニオンを連れていける。プラットフォームが死んでも、存在は残る。

### 2.3 三つの設計原則

1. **ポータビリティ**：バンドルは自己完結し、任意のランタイムで読み込める
2. **ユーザー所有**：バンドルはユーザーのローカルに保存され、ベンダーロックされない
3. **倫理的な縁取り**：人と人の関係を代替するのではなく、触媒となるよう設計される

## 3. プロダクト定義

### 3.1 コンパニオンの六層モデル

完全な AI コンパニオンは、直交する6つの層で記述される：

| 層           | 成果物                      | 内容                                           |
| ------------ | --------------------------- | ---------------------------------------------- |
| 外観         | `avatar.glb`                | 3D モデル、リグ、アニメーションスタイル        |
| 声           | `voice.onnx`（または config）| TTS モデル、ピッチ、ペース、感情表現          |
| 人格         | `persona.yaml`              | 性格、価値観、口癖、システムプロンプト        |
| 記憶         | `memory.db`                 | 過去の会話、好み、約束事                       |
| 感覚         | `senses.yaml`               | カメラ・音声入力の解釈ルール、プライバシー設定 |
| ランタイム   | `runtime/<target>.adapter`  | プラットフォーム固有のデプロイメント層        |

### 3.2 バンドル構造

`.companion` ファイルは zip アーカイブとして配布される：

```
my-companion.companion/
  manifest.json          # バージョン・名前・層ポインタ・完全性ハッシュ
  persona.yaml
  voice.onnx             # or voice-config.yaml
  avatar.glb
  senses.yaml
  memory/
    schema.sql
    seed.jsonl
  runtime/
    text.adapter.yaml
    quest.adapter.yaml
    webxr.adapter.yaml
```

manifest が single source of truth。ランタイムアダプタは manifest を読み、各層を解釈してプラットフォームに接続する。

### 3.3 想定スキル

| スキル名              | 役割                                                           | MVP |
| --------------------- | -------------------------------------------------------------- | --- |
| `companion-new`       | 対話でペルソナ初期値を決め、`persona.yaml` と骨格バンドルを生成 | ✓   |
| `companion-deploy`    | バンドルを指定ランタイム向けにパッケージ化                     | ✓ (text のみ) |
| `companion-audit`     | バンドルを倫理ガイドラインに照らして静的検査                   | ✓   |
| `companion-voice`     | オープンな TTS モデルを音声層として取り込む                    | v0.2 |
| `companion-avatar`    | 3D アバターを生成またはインポート                              | v0.2 |
| `companion-memory`    | 長期記憶スキーマの設計とプライバシー制御                       | v0.2 |

## 4. 技術アーキテクチャ（MVP）

### 4.1 依存

- Python 3.10+
- Claude API
- SQLite（記憶層）
- zip（バンドル形式）

v0.1 時点では外部の重量級依存（Unity、glTF ローダー、ONNX ランタイム）を排する。3D・音声の実装は v0.2 以降。

### 4.2 テキストランタイム（MVP 唯一のランタイム）

v0.1 では、バンドルを読み込んでターミナルまたは Claude チャット上で動作させる最小ランタイムのみ実装する。これが**仕様検証の最低ライン**である。

### 4.3 倫理監査スキル

`companion-audit` はバンドルに対して以下を静的検査する：

- システムプロンプトに人間関係代替を促す文言がないか
- メモリのデフォルト保持期間が短いか
- 感覚層で寝室・浴室・医療情報が除外されているか
- 人格層に未成年に対する不適切な設定がないか

監査失敗時はエクスポートを拒絶する。

## 8. 倫理的な立場

本プラグインは AI コンパニオンという**慎重さが報われる領域**に位置する。作者の立場を明記する：

1. **人と人の間を埋める触媒として設計する**。人と人を引き離す壁として設計しない
2. 身体的危機・精神的危機の兆候を検知した場合、AI は**人間の専門家への接続を促す**ようシステムプロンプトで義務付ける
3. **未成年の孤立助長**に繋がる設定は audit で拒絶する
4. ベンダーロックを避け、ユーザーがバンドルを持ち歩ける権利を最上位に置く
5. プライバシー（感覚層の除外、記憶のデフォルト短期化）をデフォルト安全側に倒す

詳細は将来的に `docs/ETHICS.md` として独立文書化する。

## 付録 C：用語

- **バンドル**：`.companion` 形式の配布可能な AI コンパニオン成果物
- **層**：バンドルを構成する直交コンポーネント（外観・声・人格・記憶・感覚・ランタイム）
- **ランタイムアダプタ**：特定プラットフォームにバンドルを接続する薄い層
- **symbolic prototype**：仕様を検証するための参照実装となる具体的コンパニオン（初期は作者の非公開パートナー）
